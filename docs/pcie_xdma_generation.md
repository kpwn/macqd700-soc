# PCIe/XDMA Generation Flow

> **Status (2026-05-02): inactive in the canonical build flow.**  The active
> `make fpga-100mhz-jtag-bitstream-dram` path uses Vivado 2025.2 with
> `ENABLE_PCIE_XDMA=0`.  The XDMA IP version pin and `check_pcie_xdma_ip.py`
> validator below are still on `xdma:4.1` rev 23 / Vivado 2023.1; re-enabling
> the PCIe path will require bumping these to `xdma:4.2` (the version Vivado
> 2025.2 ships) and re-validating against pcie_test source.

This repo owns the PCIe/XDMA generation recipe in
`synth/gen_pcie_xdma.tcl`. Generated Vivado output stays under
`build/pcie_xdma/` and is not checked in.

## Source Inputs

The XDMA parameters come from the known-good `pcie_test` project:

| Artifact | Path |
|---|---|
| XDMA XCI source of truth | `/offlinenas/share/FPGA/pcie_test/pcie_test.srcs/sources_1/bd/design_1/ip/design_1_xdma_0_0/design_1_xdma_0_0.xci` |
| Legacy OOC DCP reference | `/offlinenas/share/FPGA/pcie_test/pcie_test.runs/design_1_xdma_0_0_synth_1/design_1_xdma_0_0.dcp` |
| Generated stub reference | `/offlinenas/share/FPGA/pcie_test/pcie_test.gen/sources_1/bd/design_1/ip/design_1_xdma_0_0/design_1_xdma_0_0_stub.v` |
| Board pin reference | `/offlinenas/share/FPGA/pcie_test/pcie_test.srcs/constrs_1/new/pcie_test.xdc` |

Active repo constraints are `synth/pcie_xdma.xdc` for the PCIe TX pins and
PERST#, and `synth/fpga_top_real_mig.xdc` for the AB7/AB6 100 MHz MGTREFCLK
pair. The generator does not copy files from `pcie_test`; it recreates the IP
from Tcl and uses the reference only for parameter-marker comparison.

## XDMA Contract

| Parameter | Value |
|---|---|
| FPGA part | `xcku5p-ffvb676-2-i` |
| IP | `xilinx.com:ip:xdma:4.1`, revision 23 in Vivado 2023.1 |
| Module | `design_1_xdma_0_0` |
| PCIe link | Gen3 x4 |
| PCIe block / GT quad | `X0Y0` / `GTY_Quad_224` |
| Reference clock | `100_MHz` |
| AXI clock | 250 MHz generated by XDMA |
| AXI data / ID / address | 128-bit data, 4-bit ID, 64-bit address |
| Active host path | `M_AXI_BYPASS`, 64-bit enabled |
| Bypass BAR | 4 MiB, `pciebar2axibar_axist_bypass=0` |
| Descriptor DMA | Generated but parked in `fpga_top.v` for now |
| Interrupts | 9 user IRQs, MSI and MSI-X enabled |

## Generate

The Makefile targets use the machine-wide Vivado lock
`/var/tmp/m68k-ooo-vivado.lock` with nonblocking `flock -n`. If another Vivado
run is active, the target exits immediately and generation remains pending.

```bash
make pcie-xdma-validate
make pcie-xdma
```

`pcie-xdma-validate` creates the configured XCI, checks the key parameter
contract without synthesizing the IP, and runs
`tools/check_pcie_xdma_ip.py` against the generated XCI and manifest.
`pcie-xdma` also runs OOC IP synthesis and writes:

```text
build/pcie_xdma/design_1_xdma_0_0.xci
build/pcie_xdma/design_1_xdma_0_0.dcp
build/pcie_xdma/design_1_xdma_0_0_stub.v
build/pcie_xdma/design_1_xdma_0_0_manifest.txt
```

## Consume

PCIe/XDMA Vivado builds default to the repo-generated IP:

```bash
make ddr4-mig
make pcie-xdma
make USE_REAL_MIG=1 ENABLE_PCIE_XDMA=1 REAL_FPGA_BUILD=1 impl
```

`synth/vivado.tcl` reads `PCIE_XDMA_XCI`, defaulting to
`build/pcie_xdma/design_1_xdma_0_0.xci`. Synthesis and implementation also
require the matching `PCIE_XDMA_DCP`, defaulting to
`build/pcie_xdma/design_1_xdma_0_0.dcp`.

Set `PCIE_XDMA_XCI=/path/to/design_1_xdma_0_0.xci` and
`PCIE_XDMA_DCP=/path/to/design_1_xdma_0_0.dcp` only for an explicit local
override. For reference comparison only, `USE_PCIE_TEST_XDMA_XCI=1` allows the
old `pcie_test` XCI fallback when no repo-generated XCI exists. Do not use that
as the normal bitstream flow.

`ENABLE_PCIE_XDMA=1` remains mutually exclusive with `ENABLE_JTAG_AXI=1`;
both are host masters for xbar M1.

## Validate

Cheap checks before a full implementation:

```bash
make pcie-xdma-validate
make pcie-xdma-dry-run
make pcie-xdma-pincheck
```

`pcie-xdma-dry-run` elaborates the real-MIG + PCIe/XDMA shell without full
synthesis. `pcie-xdma-pincheck` parses the DDR and PCIe pin constraints with
the same shell. Both targets depend on `pcie-xdma-validate` so the repo-owned
XCI exists before `synth/vivado.tcl` reads it.

Remaining manual validation is hardware-level: PCIe link training on the
KU5P board, host enumeration with the Xilinx XDMA driver, bypass BAR reads and
writes, and timing closure for the real-MIG/core/PCIe/HDMI clock set.
