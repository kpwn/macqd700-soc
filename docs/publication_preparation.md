# Source publication preparation — 2026-09-19

The release uses a fresh source snapshot, not the existing development Git
history. The destination is `https://github.com/kpwn/macqd700-soc`.

## What changed

- Removed four tracked timing/trace logs from `logs/p140` and `logs/p141`.
- Removed ten one-off p133–p142 build launchers. They encode superseded
  bisect arms, diagnostic assumptions or private worktree paths. The normal
  `tools/build_bitstream.sh` entry point remains. The reusable JTAG REPL
  launcher `tools/p141_start_repl.sh` and diagnostic readers remain.
- Removed `rtl/mac/adb_pic_fw.hex` from the index. It was genuine firmware,
  not project-authored RTL. `make prepare-adb-firmware` now converts a
  user-supplied dump; the generated bytes match the former file exactly.
  Hardware builds fail explicitly if the local firmware is unavailable.
- Added artifact/firmware ignore rules and an indexed-tree publication check.
- Corrected README clock, CPU-default and ADB requirements, and factual Taxi
  vendoring descriptions in README/LICENSE. License choices are unchanged.
- Made Ethernet lint use the same generated-CPU warning policy as the other
  top-level lint targets (`CPU_EXTRA_LINT_FLAGS`); it previously failed on
  the generated CPU's existing `VARHIDDEN` warning.
- Added archive exclusions for private coordination and two large chronological
  investigation journals. These files remain in the development repository.
- Removed 787 unused Taxi board-example files, including broken upstream-test
  links. The expanded Ethernet source list and content hashes are unchanged.
  Retained source provenance and local modifications are documented in
  `vendor/rk5-eth/VENDORING.md`.
- Added explicit README firmware setup and guarded raw SD `dd` instructions.
  `tools/test_readme_sd_layout.py` executes the exact documented writes and
  read-back comparisons on synthetic files, checks PRAM preservation, and
  proves that a wrong HDD offset fails the check.

All removed tracked files remain recoverable from development commit
`b22df792` and its ancestors. The immutable working 200 MHz build is unchanged.
Small regression binaries, peripheral trace vectors, test sources, architecture
contracts and third-party license files are deliberately retained.

## Checks

```sh
python3 tools/test_prepare_adb_firmware.py
python3 tools/test_check_publication.py
python3 tools/test_readme_sd_layout.py
python3 tools/check_publication.py
```

The publication check examines the **Git index**, including staged changes.
Stage intended release changes first. It rejects common generated artifacts,
known firmware paths, unexpected binary files, escaping symlinks and several
credential signatures. It is not a comprehensive secret or provenance audit.
Ignored firmware/build products never become publication inputs.

## Reproducing the source export

1. Use a fresh source snapshot. **Do not
   simply push this development history**: deleting a file at the tip leaves
   earlier versions reachable, including the ADB firmware removed here.
   `.gitattributes` exclusions apply to `git archive`, not ordinary pushes.
2. Run `python3 tools/export_publication.py /new/nonexistent/directory`.
   It exports only committed files, honors archive exclusions, creates one
   root commit, restores the exact CPU gitlink and sets no remote. It refuses
   dirty tracked files or an existing destination. Initialize CPU from GitHub
   in the result, rather than copying a local generated/build tree.
3. Test that fresh checkout using only documented tools and user-supplied
   firmware. Verify the normal synth, lint and test entry points; historical
   targets still contain references to the retired `cpu/` implementation.
4. Review remaining historical docs, diagnostic scripts and vendored Taxi
   examples for relevance. Do not prune source or file lists solely by filename:
   Taxi's nested relative file lists and symlinks are live dependencies.
5. Review complete third-party provenance, license notices and embedded data.
   Prebuilt FPGA images are separate, explicitly requested release assets:
   the working image embeds ADB firmware and its notes must state that fact.
6. Inspect the final exported inventory and scan its contents again before
   publishing. For updates to the existing public repository, use normal
   commits based on its public history; never force-push the development
   repository over the fresh public history.

The older `docs/release_audit.md` is historical, not current evidence: its
claims about absent licenses, firmware paths and CPU layout have drifted.
