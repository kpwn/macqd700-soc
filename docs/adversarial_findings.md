## Bug class breakdown

**5 distinct bugs surfaced**:

1. **LSU unaligned WORD at ea[1:0]==3** (`adv_word_at_odd3`).  Self-
   documented FIXME in `rtl/core/mem/lsu.v:372`.  Store drops bytes;
   load returns wrong data.  See `tb/fuzz_fails/BUG_lsu_word_odd3.md`.

2. **MOVEM with An in its own register list** (`adv_movem_an_in_list`)
   — FIXED.  MOVEM predecrement stores now preserve the original A7;
   postinc loads no longer overwrite the loaded A7.  Regression test:
   `tb/tests/asm/adv_movem_an_in_list.s`.

3. **RTS with unaligned A7 (split-LONG pop)** (`adv_rts_unaligned_a7`)
   — FIXED in `db5ac6b`.  `lsu.v` S_LD_WAIT2 branch-completion bundle
   now sets `cmpl_br_taken`/`cmpl_br_target` for `cur_is_rts` on the
   split path.  Regression test: `tb/tests/asm/adv_rts_unaligned_a7.s`.

4. **BSR/RTS with (A7) rewritten between push and pop**
   (`adv_bsr_rts_a7_modified`) — FIXED.  Root cause was BSR-push
   store-to-A7 not landing in cache before the RTS-LOAD reads it,
   not RAS / load-target mispredict.  Regression test:
   `tb/tests/asm/adv_bsr_rts_a7_modified.s`.

5. **Second store-to-same-address races on RTL**
   (`adv_alias_init_store`) — FIXED.  Resolved by adding the
   MOVE.L #imm32,(An) decode (the seed program landed via the V2
   decoder).  Regression test: covered by adversarial alias tests.

## Regression gates (11)

The remaining 11 tests BOTH pass — they are CORRECTNESS regression
gates for invariants that currently hold.  A future change that
regresses any of these must be caught by this test set.

## Test set methodology

- Each test targets ONE architectural assumption (see `Key RTL Design
  Decisions (DO NOT regress these)` in CLAUDE.md, or an `INVARIANT` /
  `FIXME` / `NOTE` in the RTL source).
- Each test carries a header comment describing the assumption and
  the expected failure mode.
- Tests use the standard PASS sentinel (`0xC0FFEE00 → 0xFFFF0000`) and
  FAIL sentinel (`0xDEADBEEF → 0xFFFF0000`).
- Tests are validated by running BOTH on the RTL and on Musashi, and
  diffing final architectural state via `tools/fuzz/fuzz.py --replay`.

Build / run:

```bash
make sim musashi-ref
make -C tb/models musashi-run
rm -rf /tmp/adv-work && mkdir -p /tmp/adv-work
for s in tb/tests/asm/adv_*.s; do
    name=$(basename $s .s)
    make asm-test ASM=$s NAME=$name
    python3 tools/fuzz/fuzz.py \
        --sim build/sim/Vmac_top \
        --musashi tb/models/libmusashi_ref.a \
        --work /tmp/adv-work \
        --as m68k-linux-gnu-as --ld m68k-linux-gnu-ld \
        --objcopy m68k-linux-gnu-objcopy \
        --replay build/tests/${name}.bin
done
```
