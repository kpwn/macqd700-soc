# DDR4 MIG Generation Flow

This repo owns the DDR4 MIG generation recipe in `synth/gen_ddr4_mig.tcl`.
Generated Vivado output stays under `build/ddr4_mig/` and is not checked in.

## Source Inputs

The DDR parameters come from the known-good `pcie_test` project, not from the
AN9134 HDMI reference:

| Artifact | Path |
|---|---|
| MIG XCI source of truth | `/offlinenas/share/FPGA/pcie_test/pcie_test.srcs/sources_1/bd/design_1/ip/design_1_ddr4_0_1/design_1_ddr4_0_1.xci` |
| Legacy OOC DCP reference | `/offlinenas/share/FPGA/pcie_test/pcie_test.runs/design_1_ddr4_0_1_synth_1/design_1_ddr4_0_1.dcp` |
| Generated stub reference | `/offlinenas/share/FPGA/pcie_test/pcie_test.gen/sources_1/bd/design_1/ip/design_1_ddr4_0_1/design_1_ddr4_0_1_stub.v` |
| Board pin reference | `/offlinenas/share/FPGA/pcie_test/pcie_test.srcs/constrs_1/new/pcie_test.xdc` |

Active repo constraints are `synth/ddr4.xdc` for the DDR pins and
`synth/fpga_top_real_mig.xdc` for the AB7/AB6 100 MHz fabric reference clock.
`files/ddr4.xdc` is an older generated-style C0-port reference and is not read
by `synth/vivado.tcl`.

## MIG Contract

| Parameter | Value |
|---|---|
| FPGA part | `xcku5p-ffvb676-2-i` |
| IP | `xilinx.com:ip:ddr4:2.2`, revision 28 in Vivado 2025.2 |
| Module | `design_1_ddr4_0_1` |
| DDR4 part | `MT40A512M16LY-075` |
| DDR4 memory period | `750 ps` |
| DDR4 input clock period | `5000 ps` |
| PHY ratio | `4:1` |
| DDR4 width | `32` bits, `DM_NO_DBI` |
| Parity/alert | disabled, no top-level parity/alert ports |
| AXI UI | 256-bit data, 31-bit address, 1-bit ID |
| UI clock | `333250000 Hz` generated by the IP |
| Address/control shape | 17 ADR, 2 BA, 1 BG, 1 CK, 1 CKE, 1 CS, 1 ODT |

## Generate

The Makefile targets use the machine-wide Vivado lock
`/var/tmp/m68k-ooo-vivado.lock` with nonblocking `flock -n`. If another Vivado
run is active, the target exits immediately and generation remains pending.

```bash
make ddr4-mig-cache-status
make ddr4-mig-validate
make ddr4-mig
```

`ddr4-mig-validate` creates the configured XCI and checks the key parameter
contract without synthesizing the IP. `ddr4-mig` also runs OOC IP synthesis and
writes:

```text
build/ddr4_mig/design_1_ddr4_0_1.xci
build/ddr4_mig/design_1_ddr4_0_1.dcp
build/ddr4_mig/design_1_ddr4_0_1_manifest.txt
```

Before taking the Vivado lock, both targets check the generated files under
`build/ddr4_mig/`. A valid validate cache needs the XCI and manifest; a valid
synth cache needs the XCI, manifest, and DCP. The manifest must match the DDR4
contract above and must include cache metadata stamped after the last successful
Makefile-driven generation: the `synth/gen_ddr4_mig.tcl` SHA-256 plus hashes of
the generated XCI and, for synth mode, DCP. On a hit the target prints one
`DDR4 MIG cache hit (...)` line and skips Vivado.

Cache invalidation is explicit: edit `synth/gen_ddr4_mig.tcl`, change or delete
the generated XCI/manifest, change or delete the DCP required by synth mode,
remove the stamped cache metadata, or switch a `ddr4-mig` synth run back to only
validate-mode outputs, and the next target run regenerates through the normal
Vivado flow.

`ddr4-mig-cache-status` is a fast synth-cache probe you can use before launching
full generation.

## Consume

Real-MIG Vivado builds default to the repo-generated DCP:

```bash
make ddr4-mig
make USE_REAL_MIG=1 REAL_FPGA_BUILD=1 impl
```

`synth/vivado.tcl` reads `DDR4_MIG_DCP`, defaulting to
`build/ddr4_mig/design_1_ddr4_0_1.dcp`, and stitches it into the
`design_1_ddr4_0_1` black box after top-level synthesis. Set
`DDR4_MIG_DCP=/path/to/design_1_ddr4_0_1.dcp` only for an explicit local
override.

For reference comparison only, `USE_PCIE_TEST_MIG_DCP=1` allows the old
`pcie_test` DCP fallback when no repo-generated DCP exists. Do not use that as
the normal bitstream flow.

## Validate

Cheap checks before a full implementation:

```bash
make ddr-reference-check
make ddr4-mig-validate
make ddr-pincheck
```

`ddr-pincheck` forces the real DDR4 top-level shell, reads `synth/ddr4.xdc`,
and runs RTL elaboration only. It does not need the OOC DCP and does not write
a bitstream.

Remaining manual validation is hardware-level: DDR calibration in this top,
real-MIG/core/HDMI timing closure, and the first boot path using the generated
DCP.
