# AN9134 50 MHz Platform Bring-up

Scope: first real hardware path for the ALINX AN9134 / AL9134 40-pin
HDMI setup, with the core clock divided from the fixed 200 MHz board
oscillator to a conservative 50 MHz.  Full-ROM runs require the DRAM-backed
MIG path; the SIM_MODEL fallback is only a tiny smoke-image path.

## 1. Pre-flight Checks

Run these from the platform worktree before any bitstream build:

```bash
make ddr-reference-check
make fpga-first-hw-offline-preflight
make fpga-50mhz-preflight
```

`ddr-reference-check` compares the repo DDR shell against both external
references: `~/FPGA/pcie_test` as the active DCP/stub contract and
`~/FPGA/9.RK-XCKU5P-F/5_FactoryData/image_ku5p` as an advisory factory pin
reference.  The factory MIG is not a drop-in replacement for the pcie_test
DCP because its memory part, timing, and AXI ID width differ.

`fpga-first-hw-offline-preflight` is the agent-safe subset: it runs the
pcie_test DDR4 comparison, Verilator FPGA-top lint, the standalone
repo-to-MIG AXI bridge contract test, `tb-clk-rst` for the 50 MHz and
100 MHz divider settings, and the framebuffer first-light checks
(`tb-video-pattern`, `tb-video-checkerboard`, and
`tb-vram-scaler-firstlight`).  It does not invoke Vivado.

`fpga-50mhz-preflight` depends on the offline target, then adds Vivado
`clock-report` and Vivado `ddr-pincheck`.  Those Vivado steps stop at RTL
elaboration/constraint parsing; they do not write a synthesized netlist,
run place/route, or generate a bitstream.

Equivalent individual commands:

```bash
make lint-fpga-top

make tb-axi-ddr4-mig-bridge

make firstlight-framebuffer-preflight

TARGET_FREQ_MHZ=50 CORE_CLK_DIVIDE=4 CORE_CLK_HZ=50_000_000 \
VIDEO_SMOKE=1 HDMI_TEST_PATTERN=1 BOOT_ROM_SECTORS=2048 \
make clock-report

make tb-clk-rst CLK_DIVIDE=4

make tb-clk-rst CLK_DIVIDE=2

TARGET_FREQ_MHZ=50 CORE_CLK_DIVIDE=2 CORE_CLK_HZ=50_000_000 \
make ddr-pincheck

make timing-audit TIMING_AUDIT_REPORT=build/vivado/reports/timing_synth.rpt
```

`clock-report` is a parse-only Vivado elaboration.  It must report the
fixed 200 MHz `sysclk200` input and the top generics:

```text
CORE_CLK_DIVIDE=4
CORE_CLK_HZ=50000000
VIDEO_SMOKE=1
HDMI_TEST_PATTERN=1
BOOT_ROM_SECTORS=2048
```

The two `tb-clk-rst` runs prove the clock divider and reset-release
sequencer at the first-light 50 MHz setting and the next 100 MHz step-up
before any board power-on claim.

`tb-axi-ddr4-mig-bridge` keeps the real-MIG handoff honest before board
runs: the current repo DDR side is
128-bit/6-ID/32-address, while the pcie_test MIG side is
256-bit/1-ID/31-address at the 333.25 MHz UI clock.

`ddr-pincheck` forces the non-`SIM_MODEL` DDR4 top-level port set,
reads `synth/ddr4.xdc`, elaborates the real DDR pin shell, and exits
before synthesis or bitstream generation.  Passing this proves the RTL
port list and board-level DDR4 pin constraints still parse.  Run
`make ddr-pcie-test-check` as the companion static comparison against the
known-good `~/FPGA/pcie_test` DDR4 project:

| Contract | Checked fact |
|---|---|
| DDR4 pins | `synth/ddr4.xdc` / `synth/fpga_top_real_mig.xdc` match the pcie_test package pins after port renaming |
| Repo real-DDR shell | `rtl/sys/ddr_ctrl.v` exposes the expected 200 MHz sys clock and DDR4 physical port directions/widths |
| MIG memory config | `MT40A512M16LY-075`, 32-bit DDR4 bus, DM-no-DBI, no parity/alert, 750 ps period |
| MIG clocks | 200 MHz differential input clock, 333.25 MHz `c0_ddr4_ui_clk` / AXI domain |
| MIG reset | active-low `c0_ddr4_aresetn`, active-high `sys_rst` generated by inverting `ddr4_mig_resetn` |
| MIG AXI boundary | generated stub ports are 256-bit AXI data, 31-bit AXI address, 1-bit AXI ID |
| Calibration | `c0_init_calib_complete` is the only real-MIG ready signal to treat as `ddr_cal_done` |

This still does not prove real DDR calibration on this top; it makes the first
hardware MIG bridge contract machine-checkable before Vivado implementation.
Missing mapped DDR4 constraints, missing mapped top-level DDR4 ports, and
`ddr_ctrl` real-DDR shell port drift are hard failures in this check because
any one of them can silently invalidate the known-good pcie_test comparison.

## 2. First Bitstream Contract

The full-ROM first hardware bitstream should use DRAM and direct HDMI bars:

```bash
make fpga-50mhz-jtag-bitstream-dram
```

Run `make fpga-50mhz-preflight` first and keep full implementation as a
PM-scheduled phase-boundary run because it consumes the Vivado mutex for
much longer than the parse-only checks.

The DRAM-backed target sets `USE_REAL_MIG=1`, `CORE_CLK_DIVIDE=2`, and
`CORE_CLK_HZ=50_000_000`: real-MIG builds use the 100 MHz AB7/AB6 fabric
clock, so divide-by-two is the 50 MHz first-light setting.  The SIM_MODEL
50 MHz checks still use divide-by-four from the 200 MHz T24/U24 board clock.

Expected board observations:

| Signal | Meaning | Expected |
|---|---|---|
| `led[0]` | `core_rst` | Low after reset release |
| `led[1]` | `ddr_cal_done` | High after real DDR4 calibration |
| `led[2]` | `boot_rom_loaded` | High after SD copy completes |
| `led[3]` | `hdmi_mmcm_locked` | High once pixel clock locks |
| HDMI | `HDMI_TEST_PATTERN=1` bars | Visible without depending on CPU, ROM, DDR, or VRAM scan-out |

The SIM_MODEL DDR fallback is 64 KiB.  A full 2048-sector ROM copy needs
1 MiB, so Vivado now blocks SIM_MODEL synth/impl for full-ROM images because
that build would wrap the ROM over the reset-vector area.  Use SIM_MODEL only
for tiny smoke images, for example `BOOT_ROM_SECTORS=16`.

The known-good pcie_test project gives the DDR4 component/config facts
(`MT40A512M16LY-075`, 32-bit bus, 750 ps memory period, 333.25 MHz UI/AXI
clock).  `make fpga-50mhz-jtag-bitstream-dram` sets `USE_REAL_MIG=1`, reads
the pcie_test OOC MIG DCP from `PCIE_TEST_DIR` (default `~/FPGA/pcie_test`),
and stitches it into this top:

| Item | Status |
|---|---|
| pcie_test DDR4/MIG pin, reset, and AXI geometry check | `make ddr-pcie-test-check` |
| Repo 128-bit/6-ID/32-address to pcie_test 256-bit/1-ID/31-address AXI shim | `make tb-axi-ddr4-mig-bridge` |
| pcie_test-equivalent MIG IP artifact imported/regenerated for this Vivado flow | OOC DCP stitched from `PCIE_TEST_DIR` |
| AXI/MIG UI clock-domain decision (`c0_ddr4_ui_clk` versus core clock) | `axi_async_bridge` crosses core clock to MIG UI clock |
| Full burst policy beyond first single-beat traffic | Pending; first-light ROM copy intentionally serializes to single-beat word writes |
| Real-MIG `fpga_top` wiring and Vivado IP artifact merge | First-pass DCP stitch path |

`tb-axi-ddr4-mig-bridge` now checks the safe first-light cases explicitly:
lower-half and upper-half forwarding, 4-byte boot_fsm/CPU accesses,
high-address rejection, multibeat rejection, wrong-size rejection, and
missing-`WLAST` rejection.

## 3. CDC Guardrails

Keep `HDMI_TEST_PATTERN=1` for first light.  It emits pclk-domain colour
bars and suppresses VRAM reads, so it validates the AL9134 pinout, reset,
I2C, pixel clock, DE/HS/VS, and RGB pins without exercising the VRAM
read path.

Use `HDMI_TEST_PATTERN=1` for the first board proof because it isolates the
AL9134/pclk path.  After that passes, `HDMI_TEST_PATTERN=0` exercises the
framebuffer scanout path through `video_top`'s `fb_reader` bridge rather than
the pclk-local test bars.

DDR remains gated by `ddr_cal_done` through `clk_rst`.  In `SIM_MODEL`,
calibration rises after the model delay.  In real-MIG mode, calibration is
`c0_init_calib_complete` from the pcie_test DDR4 IP and `core_rst` stays
asserted until calibration completes.

Vivado timing reports must be audited before any bitstream signoff:

```bash
make timing-audit TIMING_AUDIT_REPORT=build/vivado/reports/timing_synth.rpt
```

For the real-MIG 50 MHz follow-up branch, point the same parser at that
branch's synth report:

```bash
make timing-audit \
  TIMING_AUDIT_REPORT=/home/qwertyoruiop/m68k-ooo-worktrees/real-mig-50mhz-bitstream-readiness/build/vivado-real-mig-50mhz/reports/timing_synth.rpt
```

Treat every negative inter-clock group, unconstrained path group, and
non-zero `check_timing` count as a blocker until reviewed.  Do not add a
`set_false_path` just because a path crosses clocks.  Safe exception
candidates are limited to boundaries where the RTL or IP proves the CDC:

| Boundary | Safe to constrain only if |
|---|---|
| Core AXI to MIG UI clock | The path is through `axi_async_bridge`, its `async_fifo` pointer synchronizers, or a vendor AXI clock converter. Direct control/data paths outside that bridge are blockers. |
| Core/VRAM to HDMI pixel clock | The path is through `fb_reader`/FIFO-style scanout CDC or the pclk-local `HDMI_TEST_PATTERN=1` path. Direct framebuffer/scaler control paths outside that CDC are blockers. |
| Async board inputs | The input is already debounced/synchronized or is intentionally treated as asynchronous reset/input in XDC. |
| VIO/debug sampling | The path is debug-observation-only and the sampled signal is not fed back into functional logic. |

Known unsafe first-hardware blockers from the real-MIG synth-only report are
the MIG UI/recovered/core clock groups, the core/pixel-clock groups, the
`pclk_unbuf` intra-clock violation, and non-zero `no_clock` /
`unconstrained_internal_endpoints` counts.  Keep those visible until the
crossing has a documented synchronizer or FIFO and the matching constraint is
reviewed.

## 4. Small-ROM Checkerboard Plan

The platform top now has a `BOOT_ROM_SECTORS` generic.  This lets a
board operator put a tiny ROM image at SD LBA 0 and shorten the boot copy
without touching `tb/tb_rom_boot.cpp` or changing `boot_fsm.v`.

For a first checkerboard experiment:

1. Build a small image whose first sector contains code reachable at the
   default reset PC `0x4000_002A`.
2. Set `BOOT_ROM_SECTORS` to the number of 512-byte sectors in that image,
   for example `BOOT_ROM_SECTORS=16`.
3. Have the stub write a simple pattern to the VRAM aperture at
   `0xF900_0000` and then loop.
4. Keep `HDMI_TEST_PATTERN=1` for the initial board proof.  Switch it to `0`
   when you want the checkerboard to prove the full VRAM -> CDC -> scaler
   display path.

This still tests SD init, `boot_fsm`, AXI widening, xbar DRAM routing, reset
release, and CPU fetch from the ROM window.  Use the DRAM-backed target for
this unless the image is small enough for the 64 KiB SIM_MODEL window.

For a probe-enabled full-ROM first-light bitstream, use the DRAM-backed JTAG
build target:

```bash
make fpga-50mhz-jtag-bitstream-dram
```

That expands to the same 50 MHz / `VIDEO_SMOKE=1` / `HDMI_TEST_PATTERN=1`
contract with `ENABLE_VIO=1 ENABLE_JTAG_AXI=1`, so Vivado emits both:

```text
build/vivado/fpga_top.bit
build/vivado/fpga_top.ltx
```

The same bitstream can bypass SD at runtime for ROM patch iteration.  Assert
VIO `probe_out0[0]` to hold `boot_fsm` in reset and keep the CPU gated, write
the DRAM-backed ROM window through the Xilinx JTAG-to-AXI master on xbar M1
using single 32-bit transactions, then set `probe_out0=0x3` to release the
CPU.  No rebuild is required to switch between SD boot and JTAG-loaded ROM
experiments; deasserting bit 0 returns the next reset to the SD path.

The batch helper for first-board JTAG control is `synth/jtag_bringup.tcl`:

```bash
make jtag-dashboard
vivado -nojournal -nolog -mode batch -source synth/jtag_bringup.tcl \
  -tclargs vio-set 0x5
vivado -nojournal -nolog -mode batch -source synth/jtag_bringup.tcl \
  -tclargs axi-read 0x40000000
vivado -nojournal -nolog -mode batch -source synth/jtag_bringup.tcl \
  -tclargs axi-write 0x40000000 0x4ef9002a
vivado -nojournal -nolog -mode batch -source synth/jtag_bringup.tcl \
  -tclargs rom-load files/420dbff3.rom 0x40000000
```

`rom-load` forces boot bypass and CPU reset while writing, then releases the
CPU with `probe_out0=0x3`.  The helper expects a bitstream built with both
`ENABLE_VIO=1` and `ENABLE_JTAG_AXI=1`, which is what
`make fpga-50mhz-jtag-bitstream-dram` produces.

Current status: the guarded real-MIG flow is explicit in the Makefile and
Vivado Tcl, and the project has moved on to a successful 100 MHz first-light
bitstream flow.  Keep this 50 MHz runbook as the conservative fallback, not as
the default target.  The remaining open items are repo-owned MIG generation,
board calibration evidence, timing closure after each hardware-facing change,
and burst policy beyond first-light single-beat traffic.

Before programming, inventory the cable and target without touching the FPGA:

```bash
make jtag-discover
```

Program dry-run is the default:

```bash
synth/program_fpga.sh
```

If the dry-run reports the expected fresh bitstream and probe file, program
and print the one-shot VIO dashboard:

```bash
synth/program_fpga.sh --go
```

For a bitstream intentionally built without VIO, use:

```bash
synth/program_fpga.sh --go --no-vio --bit build/vivado/fpga_top.bit
```

## 5. Stop Conditions

Stop and report instead of forcing the build if any of these occur:

| Condition | Meaning |
|---|---|
| `make fpga-50mhz-preflight` fails | Do not start implementation; inspect the failing lint/elab/pin step |
| `clock-report` does not show `CORE_CLK_DIVIDE=4` / `CORE_CLK_HZ=50000000` | Clock plan mismatch |
| `ddr-pincheck` fails | DDR4 port/XDC shell is not safe to hand to Vivado |
| `USE_REAL_MIG=1 make impl` cannot find the pcie_test MIG DCP | Set `PCIE_TEST_DIR` or regenerate/import the DDR4 IP |
| `led[3]` stays low | HDMI MMCM or reset problem |
| HDMI bars are absent with `led[3]` high | AL9134 pinout/I2C/output-timing issue |
| Vivado reports AL9134 `HDIOLOGIC` min-period or pulse-width violations | Do not flash; keep RGB/sync launch flops out of IOB packing and avoid the ODDRE1 forwarded-clock path at 148.5 MHz |
