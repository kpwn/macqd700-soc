# Root cause: test-side typo in the MOVEM.L D0-D7/A0-A7 check.

# mmu_nested_fault — FIXED task #214 / D3 (2026-04-24).
# Two-part root cause:
#   (a) MMU `last_fault` is a 1-cycle sticky bit from the most recent
#       walker completion, and the old `assign fault = ... | last_fault`
#       would surface that stale bit on any subsequent probe -- even
#       ones hitting a TTR/ATC and therefore not using the walker at
#       all.  Guard with `need_walk` so TTR-hits can't inherit a
#       prior walker's fault.  Fix in rtl/core/mem/mmu.v.
#   (b) The exception sequencer needs exclusive AXI access while it
#       pushes frames / reads vectors, but speculative LSU issues
#       dispatched past the faulting uop can re-arm the walker after
#       flush_en cleared iq_mem, stalling the sequencer's push.
#       Gate LSU-side mmu_req_valid with !exc_active in
#       m68k_core_memory.vh so the walker never picks up a stranded
#       speculative load.

# irq_during_rte — UN-DEFER'd 2026-05-03.  Audit bug #3 fixed.
# Two RTL changes:
# (1) exception.v exposes a new `inject_active` continuous output
#     (= state != S_IDLE).  Wired through m68k_core_commit.vh into
#     commit.v's take_irq predicate so a fresh IRQ cannot preempt
#     an in-flight exception entry / RTE pop sequence.  Without
#     this, take_irq's flush_en squashes the still-pending inject
#     µops mid-sequence (between take_rte and take_rte_finalize,
#     arch_sr.I is still the supervisor level so ipl_above_mask
#     remains true; same hazard in the IRQ-entry inject path).
# (2) take_irq additionally blocks when the ROB head is a STORE
#     (rob_is_store=1) so the dedicated store-fire path can pulse
#     commit_store_en before the IRQ flush; otherwise the LSU
#     would still be in S_ST_BUF and the flush would discard the
#     buffered store entirely (S_ST_BUF + flush_en → S_IDLE in
#     lsu.v).  Two test-side touch-ups: initialise HANDLER_SR=0
#     so a stale BRAM read can't confuse the no-IRQ branch, and
#     mask the saved-SR check to the supervisor half (CCR low byte
#     varies per injection cycle based on which CMP last ran).

# prm_trace_t1_before_next — UN-DEFER'd 2026-05-14 (task #34).
# Fix has three parts:
#   (a) RTL: add `!trace_pend` to normal-retire + store-retire gates
#       in commit.v so neither path retires past the traced macro's
#       last_uop while trace_pend is armed.
#   (b) RTL: clear arch_sr[15:14] (T1/T0) at take_trace itself (not

#       infinite-loop.  Saved-SR (frame push) captures the pre-trace
